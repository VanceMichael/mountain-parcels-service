# 资料及协作方约定

运行实例由 service_id 和 operating_date 唯一标识，display_number 仅显示。区间按 stops 相邻对构成，起站占用、讫站释放；额定重量为公斤、箱位为同时在车的不同容器数，满载小于等于限额。同一箱混装取最远途中的实占位置，拆箱后的新箱有独立身份。交接序号以同一封包的 source_sequence 为依据，冲突事实需核实，不能按上传时刻倒推保管。代领授权按封包列表及站点，不从同姓或手机号相同合并身份。

所有人员、地点、资产、权利和外部流水均为本地合成，不对应真实账号。`catalog.json` 的每项记录有 `id`、`kind` 和 `refs`；`refs` 只表达资料关联，不能把关联当作已经审批、支付或交付。各 kind 的其余字段直接表示记录中的业务事实；空值表示未确认，不代表零或否。`principals` 是演练身份与归属映射，不是认证凭据。

## 回放 HTTP

协作方使用标准库 HTTP 服务，默认仅监听环回地址。`POST /commands` 的 JSON 对象为 `command_id`、`operation`、`request`，三者按 `commands.json` 对应流水传入；请求内容与记录不符返回400。重复提交相同流水只受理一次，不重新开始观测片段；目录中未定义流水不受理。该回放器不是任意业务请求接口，也不会计算资格、可用数量、权限、应限制范围或应付金额。

每笔流水的首次 HTTP 状态由 `response_status` 给出，202表示已收到，504表示响应不明但协作方可能已受理，不能据此认定业务失败。`GET /commands/流水ID` 逐次返回 `observations` 的外部事实，最后一条保持稳定；查询尚未受理的流水返回404。持久状态只保存回放进度。观测列表顺序控制何时读到消息，消息内的事实时间、修订号或序号才表达来源顺序。

这些流水可用于本地接入和恢复检查，使用者也可在另一个资料副本中添加同格式的合成流水。目录没有预先给出业务服务的最终状态、审批结论或处置步骤。
